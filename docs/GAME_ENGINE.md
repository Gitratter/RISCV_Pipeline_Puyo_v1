# ぷよぷよ風ゲーム処理器の設計と検証

## 1. 研究上の位置付け

`rtl/game/PuyoEngine.v` は、RISC-V CPU に接続するゲーム専用のハードウェア処理器である。移動先の計算、衝突判定、落下、連結探索、消去、連鎖、得点計算を Verilog の状態機械が実行する。一方、CPU は開始、左右移動、左右回転、高速落下、再開始の全操作を MMIO 経由で仲介し、得点などの状態を読み出す。物理ボタンからゲーム処理器への操作バイパスは設けていない。

具体的には `firmware/puyo_supervisor.S` が、起動時に `SW` で `0x2000` の開始許可を設定し、その後のループで `LW 0x2010` によりデバウンス済みイベントと高速落下の保持状態を取得する。取得値を `SW 0x2014` でアクションレジスタへ渡すことで、ゲーム処理器への移動・回転パルス、高速落下レベル、再開始パルスを発生させる。さらに `LW 0x2008` で得点を読み、従来の LED MMIO に書く。したがって CPU の命令実行とロード・ストアが実際の操作経路に含まれる。

ただし、操作要求の発行とゲーム規則そのものの計算は区別する。本実装をそのまま「RV32I プログラムが衝突判定や消去探索を含む全ゲーム処理を実行する」と記述してはならない。卒業論文では「パイプライン CPU が MMIO を介して操作を仲介し、専用ハードウェアがゲーム規則を実行する構成」と説明する。

この分離によって、CPU の命令メモリ容量、ロード待ち時間、映像走査の締切、盤面探索の処理時間を混同せず、それぞれを独立に検証できる。将来のソフトウェア移行では本処理器の盤面・入出力仕様とテスト盤面を参照モデルとして使用できる。

## 2. 座標・色・操作中の組

盤面は 6 列×14 行である。左上が `(x,y)=(0,0)`、右下が `(5,13)`。`y=0,1` は出現・回転に用いる非表示領域、VGA に通常表示する範囲は `y=2..13` の 12 行である。非表示領域も固定後の落下・探索・消去の対象とする。

盤面配列は `board[y*6+x]`、外部へ渡す平坦化信号は `board_flat[(y*6+x)*3 +: 3]` である。`0` を空白、`1..4` を色番号とし、実際の RGB 値や図形は描画モジュールが決定する。

操作中の組は盤面配列に書き込まず、軸の `active_x/active_y`、向き `orientation`、色 `color_a/color_b` に分けて保持する。軸が色 A、軸に付随するもう一方が色 B である。

| orientation | 色 B の位置 |
|---:|---|
| 0 | 軸の上 `(x,y-1)` |
| 1 | 軸の右 `(x+1,y)` |
| 2 | 軸の下 `(x,y+1)` |
| 3 | 軸の左 `(x-1,y)` |

出現位置は軸 `(2,1)`、向き 0、色 B が `(2,0)`。表示中の `next_a/next_b` をそのまま新しい操作中の組へコピーし、その後に次の予告組を生成する。組の一方だけが別の色へ差し替わることはない。

移動・回転は変更後の 2 マスについて、両方の座標範囲を確認してから盤面を読み、両方が空白のときだけ成立する。壁蹴りとクイックターンは実装しない。回転失敗では向きと位置を保持する。左右の移動パルスが同時に入力された場合は移動しない。左右回転が同時の場合も回転しない。

同じクロックで複数の操作が重なった場合は、左右移動、回転、落下の順に候補位置を計算する。成功した移動後の位置を基準に回転、成功した回転後の向きを基準に落下判定を行う。この優先順位は再現可能なテストのために固定している。

## 3. 入力と時間の扱い

`move_left/right`、`rotate_left/right` は 1 クロック幅のパルス、`soft_drop` はレベル入力である。物理ボタンの 2 FF 同期化、デバウンス、押下検出、左右移動の長押し反復は入力モジュールの責務である。ゲーム処理器はデバウンスされた入力だけを受け取る。

入力が無効になる連鎖処理中は、各操作入力を読み取らない。パルスをキューに保存して次の組へ持ち越す機能も設けない。外部入力モジュールが生成したパルスは、その時点で `S_ACTIVE` の場合だけ有効である。

全状態は `clk` の立上りで更新する。`tick_ms` は 1 ms ごとの 1 クロック幅のイネーブルであり、新しいクロック信号ではない。ゲーム周期を変更しても CPU や VGA のクロック周波数は変わらない。

| パラメータ | 標準値 | 役割 |
|---|---:|---|
| `AUTO_DROP_MS` | 700 | 通常落下で 1 マス進む間隔 |
| `SOFT_DROP_MS` | 40 | 下ボタン保持中に 1 マス進む間隔 |
| `FALL_STEP_MS` | 40 | 固定後の重力処理 1 パス後の表示時間 |
| `CLEAR_DELAY_MS` | 180 | 全対象確定から同時消去までの表示時間 |

落下タイマーは 1 個で、下ボタンの保持状態によって比較するしきい値を切り替える。通常落下の途中で高速落下に切り替えると、既に経過した時間が高速落下のしきい値以上であれば次の `tick_ms` で落下する。落下に成功しても失敗してもその都度タイマーを 0 に戻す。0 または 1 を指定した時間パラメータは次の `tick_ms` で進む設定として扱う。

`start_enable` が立つまでリセット後のゲームは開始しない。開始後に 0 に戻しても一時停止しない。`restart` は 1 クロックの再開始要求で、全状態で最優先に処理する。再開始後も `start_enable` が 1 なら新しい組を出現させる。

## 4. 盤面の更新と状態遷移

盤面レジスタを書き込むのは `PuyoEngine` 内の 1 つの `always @(posedge clk)` だけである。固定、重力、消去、初期化、デバッグ書込みはこの処理の排他的な分岐とする。別の always ブロックから同じ盤面へ書き込まない。

```text
WAIT → SPAWN → ACTIVE → LOCK → GRAVITY_INIT → GRAVITY
          │                                      │
          └ 出現不可 → GAME_OVER                  ├ 動いた → FALL_WAIT → GRAVITY_INIT
                                                 └ 全て静止 → SCAN_INIT → SCAN
                                                                            │
                                                 未探索成分 → BFS_POP ⇄ BFS_NEIGHBOR
                                                               │
                                                   4 個以上 → MARK → SCAN
                                                   3 個以下 ───────→ SCAN
                                                                            │
                                  全盤面探索完了・対象あり → CLEAR_WAIT → CLEAR → GRAVITY_INIT
                                  全盤面探索完了・対象なし → SPAWN
```

| state_debug | 状態 | 処理 |
|---:|---|---|
| 0 | WAIT | CPU からの開始を待つ |
| 1 | SPAWN | 出現可否を確認し、次の予告組を生成 |
| 2 | ACTIVE | 移動・回転・通常／高速落下 |
| 3 | LOCK | 組の 2 マスを盤面に固定 |
| 4 | GRAVITY_INIT | 重力走査を列 0・行 12 から開始 |
| 5 | GRAVITY | 1 セルずつ下が空白か確認して落下 |
| 6 | FALL_WAIT | 落下後の盤面を一定時間表示 |
| 7 | SCAN_INIT | 訪問済みフラグ・消去マスクをクリア |
| 8 | SCAN | 84 セルを走査し、未探索の連結成分を探す |
| 9 | BFS_POP | キューから次の探索元セルを取得 |
| 10 | BFS_NEIGHBOR | 左・右・上・下を 1 方向ずつ確認 |
| 11 | MARK | 4 個以上の成分の全セルを消去対象にする |
| 12 | CLEAR_WAIT | 対象を表示し、消去前の時間を確保 |
| 13 | CLEAR | 全対象を同一クロックで消去し、得点・連鎖を更新 |
| 14 | GAME_OVER | 再開始要求を待つ |

### 4.1 固定と重力

落下を試みた際に 2 マスのいずれかが進めなければ、直ちに組を固定する。接地猶予時間は設けない。固定した 2 個は、その後は独立した盤面セルとして扱う。

重力は各列の下側から上側へ走査する。行 12 から行 0 の順で、空白でないセルの 1 行下が空白なら 1 マス移動する。6 列分、合計 78 回の判定を 1 パスとする。各セルは 1 パスで高々 1 マス進み、列内の上下関係は保持される。最後のセルが動いた場合も含めて、パス内で一度でも落下したら `FALL_STEP_MS` 待ってもう 1 パス行う。全パスを通して一度も動かなかった場合だけ消去判定へ進む。

横向きの組を段差に固定した場合、支持のある方は残り、下が空いている方だけが落下する。落下途中では消去判定を行わない。1 パスのセル更新そのものは複数クロックなので完全なフレーム単位の同時描画ではないが、25 MHz なら走査部分は 78/25 MHz ≒3.12 μs と短く、パス後に設定した表示時間を確保する。

### 4.2 上下左右の連結探索

幅優先探索（BFS）により、同色の連結成分を求める。再帰は用いない。最大 84 個のセル番号を保存できるキュー、84 bit の訪問済みフラグ、読み出し位置 `head` と書込み位置 `tail` を使用する。

セルをキューへ追加した時点で訪問済みにするため、同じセルを二重に追加しない。探索元 1 セルに対して左右上下を 1 方向／クロックで調べる。範囲内の隣接セルであることを確認した後にのみ配列を読む。斜めは隣接扱いにしない。盤面の最大セル数が 84 と既知なのでキューも探索回数も有限である。

ある成分の探索が終わり、キューに入った個数が 4 個以上なら、その成分を `clear_mask` に記録する。この段階では盤面を消さない。すべてのセルの探索が終了するまで、ほかの成分についても同じ処理を続ける。したがって離れた複数の消去対象を同じ段階で確定できる。

`clear_mask` は MARK 中から順に蓄積される。全体判定が終了した状態は `state_debug==12`（CLEAR_WAIT）である。描画で確定済み対象だけを点滅させる場合は、CLEAR_WAIT または CLEAR のときにマスクを使用する。探索途中のマスクを使っても盤面値自体は変化しないが、完成前の対象が順に点滅して見える。

### 4.3 消去、連鎖、得点

探索完了時に対象があれば `CLEAR_DELAY_MS` 待ち、マスクに含まれる全セルを同一クロックで 0 にする。同じ段階で離れた 2 群が消えても、連鎖数の加算は 1 回だけである。その後、重力・全体探索へ戻り、対象がなくなるまで繰り返す。

各消去段階の加点は次式である。

`加点 = その段階で消えた総個数 × 10 × 更新後の連鎖数`

1 回目の消去は 1 連鎖として計算する。現在の組の連鎖数 `chain` は次の組を出現させる段階で 0 に戻す。`last_chain` は直前の消去段階の連鎖数を保持するため、次の組の操作中も結果を表示できる。消去のない組では以前の `last_chain` を保持する。32 bit スコアが上限を超えた場合は通常の 32 bit 加算として折り返す。

全ての落下・消去が終わった後に、次の組の出現 2 マス `(2,1),(2,0)` が空いているかを確認する。いずれかが占有されていればゲームオーバーとする。原作の敗北判定を完全再現するものではなく、本実装の簡易ルールである。落下前や連鎖中の一時的な出現マス占有で早期終了しない。

## 5. 疑似乱数と固定出現列

通常は 16 bit LFSR を用いる。初期値は `16'hACE1`、フィードバックは bit 15,13,12,10 の XOR とし、1 組を生成するごとに 4 回進める。2 bit ずつを 1..4 に変換して 2 色を得る。2 個が同じ色になることも許可する。暗号用乱数や実際の乱数ではなく、リセットごとに同じ出現列になる再現可能な疑似乱数である。

`FIXED_SEQUENCE=1` では 256 組の ROM を順に消費し、末尾の次は先頭へ戻る。ファイル未指定時の標準列は `(1,1),(2,1),(3,1),(4,1),(1,2),...,(4,4)` を繰り返す。`SEQUENCE_FILE` に `$readmemh` 対応のファイルを指定すると任意の固定列に置き換えられる。各行は `{色B[2:0],色A[2:0]}` の 6 bit 値を 16 進数で表す。例えば `(A,B)=(1,1)` は `09`、`(2,1)` は `0a`、`(4,4)` は `24`。色は各 1..4 とし、原則 256 行を用意する。相対パスはシミュレータや Vivado の作業ディレクトリが基準になる。

## 6. テスト用インターフェース

実機では `ENABLE_DEBUG=0` とし、デバッグ端子を 0 に接続する。テスト時だけ 1 に設定する。`dbg_mode=1` の間は通常の状態機械を凍結し、以下の要求だけを処理する。同期リセットと restart は凍結中も優先する。

| 要求 | 処理 |
|---|---|
| `dbg_we` | `dbg_addr=0..83` のセルへ色 `dbg_data=0..4` を書き込む |
| `dbg_resolve` | 操作中の組を無効化し、重力→探索→消去のテストを開始する準備 |
| `dbg_set_active` | 指定した軸・向き・2 色を操作中の組に設定。占有／範囲違反なら拒否 |
| `dbg_mode=0` | 通常実行へ戻す |

`dbg_resolve` は連鎖と探索状態をリセットするが得点は保持する。各独立テストの開始では reset を行って得点も初期化する。`dbg_we` と開始要求は別クロックで与え、最後の書込みが反映されてから探索を開始する。

## 7. 自己判定テスト

`sim/tb_puyo_engine.v` は `$fatal` によって不一致を検出する。波形の目視だけに依存せず、最終盤面、消去回数、個数、得点、次の組、内部探索状態を照合する。

必須の確認項目と、シミュレーションログに現れるテスト名の対応は次のとおり。番号は続く 23 シナリオ一覧と一致する。

| 必須の確認項目 | 該当番号・PASS テスト名 |
|---|---|
| 3 個は残り、4 個・5 個以上は全消去 | 1 `three do not clear`、2 `four clear, score 40`、3 `five clear, score 50`、19 `all 84 cells: bounded queue handles largest component` |
| L 字・正方形は消え、斜め接続は消えない | 4 `L shape clears`、5 `square clears`、6 `T shape clears`、7 `diagonal-only four do not clear` |
| 離れた対象を同じ段階で消去 | 8 `full-board discovery, simultaneous clear, no partial mutation` |
| 段差上の横組で支持のない側だけ落下 | 9 `horizontal step landing: independent stable gravity` |
| 既知の 2・3 連鎖の最終盤面と連鎖数 | 10 `known two chain: empty board, 120 points`、11 `known three chain: 4/5/4, empty board, 260 points` |
| 壁・上端・底で範囲外アクセスや上書きなし | 12 `left/right/top/bottom bounds, no kicks, opposite-input cancellation`、13 `collision rejection never overwrites fixed cells` |
| 連鎖中に操作しても盤面が壊れない | 14 `all controls during resolution cannot corrupt board` |
| 次の組と実際の出現の一致 | 15 `deterministic next preview and identical-color pairs` |
| ゲームオーバーとリスタート | 16 `game over only after settling, restart clears state`、18 `restart during search clears queue state and all counters` |

加えて各クロックで、盤面に不定値がないこと、操作中の 2 マスが範囲内で固定セルと重ならないこと、探索キューが `head <= tail <= 84` を満たすことを監視する。これらは最終盤面の一致だけでは見落とし得る途中状態の不具合を検出するためである。

| 番号 | 確認項目 |
|---:|---|
| 1 | 同色 3 個を保持 |
| 2 | 同色 4 個を全消去、40 点 |
| 3 | 同色 5 個を全消去、50 点 |
| 4–6 | L 字、正方形、T 字を消去 |
| 7 | 支持された斜め 4 個を消去しない |
| 8 | 離れた 2 群を同じ段階で消去。探索中の盤面不変 |
| 9 | 段差上の横組を固定後、支持されていない片方だけ落下 |
| 10 | 既知 2 連鎖、消去個数 4→4、最終空盤面、120 点 |
| 11 | 既知 3 連鎖、消去個数 4→5→4、最終空盤面、260 点 |
| 12 | 左壁・右壁・上端・底、回転失敗、左右同時押し |
| 13 | 固定セルへの移動・回転を拒否し、上書きしない |
| 14 | 連鎖中に全操作入力を与えても結果が変化しない |
| 15 | 予告組と実際の出現一致、同色組の許容 |
| 16 | 全処理後のゲームオーバーと再開始 |
| 17 | 非表示 2 行を含む消去 |
| 18 | BFS 途中の restart で盤面・訪問済み・キュー位置・得点を初期化 |
| 19 | 全 84 セルが同色の最大連結成分、840 点 |
| 20 | 落下で隙間をなくし、列内の上下関係を保持 |
| 21 | clk だけでは落下せず、通常 10000 tick と高速 2 tick を別に検証 |
| 22 | 消去待ち時間を満たすまで盤面を保持し、その後に同時消去 |
| 23 | CPU の start_enable による開始待ち |

2 連鎖の初期盤面は、列 0 の行 10..13 を赤、列 0 の行 9 と列 1..3 の行 13 を青とする。赤 4 個が消えると上の青が底へ落ち、青 4 個がつながる。

3 連鎖は、列 0 の行 10..13 を赤、行 8,9 を青、行 7 を緑とし、列 1..3 の行 13 を青、行 12 を緑とする。赤 4 個→青 5 個→緑 4 個の順に消える。青が 2 個積まれた列 0 だけ緑の高さが異なるため、緑は青の消去後に初めて 4 個つながる。

本テストの合格は機能シミュレーションの結果であり、実機の映像表示、配置配線後のタイミング成立、ボタン操作感を確認したことにはならない。これらは統合プロジェクトで別途確認する。

## 8. 合成上の特性と今後の変更箇所

定数回数の for ループを使うのは 84 セルの初期化・同時消去、16 bit LFSR の 4 回更新、固定 ROM の初期化である。実行時データに応じた無制限 while、再帰、動的メモリ確保、ゲーム RTL 内の `#delay` はない。

盤面は 252 bit と小さく、多地点の読出し、組の同時固定、マスクによる同時消去、全体リセットを行うため FF を中心とする小規模レジスタ配列を意図している。CPU のデータ RAM をこの配列で置き換えたわけではない。BFS キューも最大 84×7 bit で、全体リセットを持つ。実際の LUT/FF 分類と必要資源数は Vivado 合成結果で評価する。

描画を画像へ変更する場合は、色番号に応じたスプライト ROM を描画側へ追加すればよく、衝突・探索・消去の処理は変更不要である。ゲーム規則を変える場合は、回転補正なら候補座標の計算、接地猶予なら ACTIVE と LOCK の間の状態、原作に近い得点なら CLEAR の加点式を変更する。これらは初版の仕様外として切り分けている。
